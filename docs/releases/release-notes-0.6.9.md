# TouchPDF 0.6.9 (16) — 打开 PDF 回归修复与工作区整理

## 原因与修复

0.6.8 新增“关闭最后一个窗口后退出”，却把启动文件选择框也算成最后一个窗口。用户点“打开”后，文件面板先关闭，PDF 文档窗口尚未建立，应用就退出了。隔离的 0.6.8 应用使用有效的双页测试 PDF 复现了此问题。

0.6.9 在启动面板及文档打开任务完成前阻止自动退出；成功打开后才解除保护。打开失败时保持错误提示，随后允许重新选择文件。真正关闭最后一个文档后仍会退出。

## 工作区

根目录建立 main 分支与整理前的 0.6.8 快照提交，保留原 GitHub origin 地址，未推送。源码移至 src/，Info.plist 移至 resources/，构建脚本与 README 位于根目录，版本记录集中于 docs/releases/。旧发布包、缓存、第三方研究源码与原空仓库元数据保存到 archive/；两份用户笔记集中于 outputs/。搬移时已逐文件核对 SHA-256，内容全部保留。

当前应用在 dist/TouchPDF.app。release/TouchPDF/dist 为指向根目录 dist/ 的兼容链接，原应用路径仍有效。应用产物、缓存、归档和用户 PDF 不进入版本控制。

## 验证

- 同一份有效 PDF：0.6.8 启动打开后进程退出；0.6.9 成功显示对应文件、两页正文和版本标题。
- ⌘O 打开第二份已有 PDF 成功；关闭第二份后第一份仍在；关闭最后一份后进程退出。
- 冷启动打开无效 PDF 显示错误；确认错误后重新出现文件选择框；再次打开有效 PDF 成功。
- 新建空白画布正常显示并保持打开；关闭后退出。
- arm64 架构、签名严格校验及 ZIP 校验通过；正式包的代码和字符串段与界面验证构建一致；旧路径解析到 0.6.9。
- 完整自检通过：快捷键状态、跨页画布、混合页面尺寸/裁切/旋转、输入恢复、保存重开、撤销/重做等。

上述 UI 验证使用隔离的应用标识及临时 PDF，未改动用户原 PDF。触控板硬件手感与单按 Shift 硬件输入不在本次验证范围内。
